1. Computer Networks, 5 Components of Data Communication & Metrics

A computer network is a set of autonomous devices (nodes / hosts) connected by communication links so that they can exchange data and share resources (files, printers, internet, compute). The course walks the whole networking stack bottom-up: bits on a wire → frames → packets → segments → applications such as HTTP and DNS.

Key concepts

  • Five components of data communication: (1) Sender, (2) Receiver, (3) Message, (4) Transmission medium, (5) Protocol. Remove any one and communication fails — a favourite 1-mark question.
  • Protocol = syntax (format), semantics (meaning of each field) and timing (when / how fast). Two devices that do not share a protocol cannot understand each other even if they are wired together.
  • Effectiveness metrics of a network: Performance (throughput, delay/latency, response time), Reliability (frequency of failure, recovery time, robustness in catastrophe) and Security (protection from unauthorised access, data integrity, recovery from breaches).
  • Throughput = actual data delivered per unit time; bandwidth = maximum capacity of the link. Throughput ≤ bandwidth, always. Latency = Transmission + Propagation + Queuing + Processing delay.
  • Network types by scale: PAN < LAN (building) < MAN (city) < WAN (country/world). The Internet is a network of networks.

Click a question to reveal the answer.

What is the difference between bandwidth and throughput?
Bandwidth is the theoretical capacity (e.g. 100 Mbps link). Throughput is what you actually achieve after protocol overhead, congestion, retransmissions and delays. Think "width of pipe" vs "water that actually comes out".
What is a protocol? Give examples at different layers.
A set of rules defining format, meaning and timing of messages. Ethernet (L2), IP (L3), TCP/UDP (L4), HTTP/DNS/SMTP (L7).
Why is the Internet called a "network of networks"?
It interconnects thousands of independently-run networks (ISPs, campuses, enterprises) using routers and the common IP protocol.

2. Transmission Modes: Simplex, Half-Duplex, Full-Duplex

Transmission mode describes the direction of flow of data between two devices on a link.

Key concepts

  • Simplex — unidirectional, like a one-way street. Uses the whole bandwidth for one direction. Examples: keyboard → CPU, TV/radio broadcast, mouse.
  • Half-duplex — both directions but not at the same time. The whole bandwidth is used by whichever side is talking. Examples: walkie-talkie, old Ethernet over a hub (CSMA/CD), CB radio.
  • Full-duplex — both directions simultaneously. Capacity is effectively doubled (or the channel is shared in two). Examples: telephone, modern switched Ethernet, TCP connection.
  • Number of links: if a link is full-duplex, collisions disappear (separate send/receive pairs) — that is why CSMA/CD is irrelevant on modern switched LANs.

Click a question to reveal the answer.

Is a TCP connection simplex, half or full duplex?
Full duplex — both ends can send and receive at the same time, with independent sequence number spaces in each direction.
Why do modern LANs not need CSMA/CD?
Switches with full-duplex links give each host a dedicated send and receive path, so no shared medium and no collisions.

📄 One-pager — Transmission Modes

  • Simplex: 1 direction (keyboard, TV)
  • Half: both, alternate (walkie-talkie, hub Ethernet)
  • Full: both simultaneously (phone, switched Ethernet)
  • Channels needed (wired): simplex 1 · half 1 · full 2 (or shared 2-way)

3. Network Topologies: Mesh, Star, Bus, Ring, Hybrid

Topology is the geometric arrangement of nodes and links — physical (how cables are laid) or logical (how data actually flows). It determines cost, fault tolerance and performance.

Key concepts

  • Mesh: every node linked to every other. Full mesh needs n(n−1)/2 duplex links and n−1 I/O ports per node. Maximum redundancy; used for backbones.
  • Star: every node connects to a central hub/switch; n links. Today's LAN standard. Central device is a single point of failure.
  • Bus: one shared backbone cable, nodes attach by drop lines/taps, terminators at both ends absorb signals to avoid reflection. Needs MAC (CSMA/CD).
  • Ring: each node connected to exactly two neighbours; data circulates (usually one direction) with token passing. Dual ring (FDDI) adds fault tolerance.
  • Hybrid / Tree: combination, e.g. stars joined to a bus backbone. Real enterprise networks are hybrid.

Which topology is most fault tolerant and which is cheapest?
Mesh is most fault tolerant; bus (or star with unmanaged switch) is cheapest.
Why are terminators needed in a bus topology?
They absorb the signal at the cable end; without them the signal reflects back and corrupts frames.
What is the single point of failure in a star topology?
The central hub/switch. Mitigation: redundant switches, stacking, link aggregation.

4. OSI Model & Layered Architecture (and TCP/IP)

Layering splits the enormous problem of communication into seven smaller, independent problems. Each layer offers a service to the layer above and uses the service of the layer below. Layers talk to their peer on the other machine via a protocol; vertically they talk via an interface.

Key concepts

  • Mnemonic (bottom→top): Please Do Not Throw Sausage Pizza Away = Physical, Data link, Network, Transport, Session, Presentation, Application.
  • Encapsulation: on the sender each layer adds its header (and the data link layer also a trailer); on the receiver headers are removed one by one (decapsulation).
  • Addressing per layer: L2 → MAC (48-bit, hop-by-hop), L3 → IP (32/128-bit, end-to-end logical), L4 → port (16-bit, process-to-process), L7 → URL / domain name.
  • Devices: Repeater/Hub (L1), Bridge/Switch (L2), Router (L3), Gateway (up to L7).
  • TCP/IP model (4 layers): Application (OSI 5-7) · Transport · Internet · Network Access (OSI 1-2). OSI is a reference model; TCP/IP is the implemented one.
  • Why layers? modularity, interoperability between vendors, easier troubleshooting (“which layer is broken?”), independence of change.
Interview trick: “Where is encryption done?” — Presentation in OSI (TLS spans 5/6 in practice); “Which layer routes?” — Network; “Which layer gives reliability end-to-end?” — Transport (TCP). Reliability of a single hop is Data Link.

Click a question to reveal the answer.

Difference between OSI and TCP/IP?
OSI: 7 layers, theoretical, strict separation of services/interfaces/protocols. TCP/IP: 4 layers, protocol-driven, practical, the one the Internet runs.
What is the PDU at each layer?
Bit → Frame → Packet → Segment (TCP)/Datagram (UDP) → Data.
Which layers are hardware-oriented and which software?
L1-L2 mostly hardware/firmware (NIC); L3 and above are software in the OS/application.
What does a switch use to forward vs a router?
Switch: destination MAC; router: destination IP with longest-prefix match.

  • Addresses: MAC · IP · Port

  • Encapsulation down, decapsulation up

5. Binary & Octet Conversion (Decimal ⇄ Binary)

IP addresses are written in dotted-decimal but processed in binary. Each of the 4 numbers is an octet (8 bits) with value 0–255. Fluency here is the foundation for subnetting.

Key concepts

  • Weights of an octet: 128 · 64 · 32 · 16 · 8 · 4 · 2 · 1 (powers of two from 2⁷ down to 2⁰).
  • Decimal → binary (subtraction method): walk the weights left→right; if weight ≤ remaining value write 1 and subtract, else write 0.
  • Binary → decimal: add the weights wherever there is a 1.
  • Memorise the “mask octets”: 128, 192, 224, 240, 248, 252, 254, 255 = 1, 2, 3, 4, 5, 6, 7, 8 leading ones. (Each = previous + next weight.)
  • Shortcuts: 255 = 11111111 · 0 = 00000000 · 2ⁿ−1 = n ones · 2ⁿ has a single 1.
  • Whole address = 4 × 8 = 32 bits; 2³² = 4,294,967,296 possible addresses.
Worked: 172 → 172−128=44 (1) → 64 no (0) → 32 yes (1) rem 12 → 16 no (0) → 8 yes (1) rem 4 → 4 yes (1) rem 0 → 2 (0) → 1 (0) = 10101100.
Whole IP: 192.168.1.10 = 11000000.10101000.00000001.00001010.

6. IPv4 Logical Addressing

An IP address is a logical, hierarchical, 32-bit address assigned to a network interface. It is split into Network ID (which network) and Host ID (which device inside it), so routers only need to remember networks, not every host.

Key concepts

  • Logical vs physical: the IP address can change when you move networks; the MAC address (48-bit, burned into the NIC) does not. Both are needed: IP finds the network end-to-end, MAC delivers the frame on each hop.
  • Hierarchy keeps routing tables small — like postal code vs house number.
  • Unicast / broadcast / multicast are the three delivery types. Unicast = one host, broadcast = all hosts of a network, multicast = a group.
  • An address belongs to an interface, not a host — a router with 3 interfaces has 3 IPs.
  • Notation: dotted-decimal (192.168.1.10), binary, or hexadecimal (C0.A8.01.0A). Network/host boundary is shown by a subnet mask or CIDR prefix /n.
  • IPv4 exhausted (2011/2015 registries). Mitigations: CIDR, NAT, private addressing, and ultimately IPv6 (128-bit).

Click a question to reveal the answer.

Why do we need both MAC and IP address?
MAC identifies a NIC on a local link (flat, no hierarchy), IP gives a hierarchical location so routers can aggregate routes across the world.
Can two hosts on the Internet have the same IP?
Not public ones. Private addresses repeat in different LANs; NAT translates them to a unique public IP.

  • Delivery: unicast · broadcast · multicast

7. Classful vs Classless Addressing (CIDR)

Classful addressing (1981) fixed the netid/hostid boundary to /8, /16 or /24 based on the first bits of the address. It was inflexible and wasteful. CIDR — Classless Inter-Domain Routing (RFC 1519, 1993) allows any prefix length written a.b.c.d/n.

Key concepts

  • Problems of classful: internal fragmentation (a 300-host company needs a Class B, wasting 65 000+ addresses) and routing-table explosion (one entry per class C).
  • CIDR notation: 192.168.10.0/26 — first 26 bits are network, remaining 6 are host. Mask = 26 ones then 6 zeros = 255.255.255.192.
  • Block rules in CIDR: size is a power of two (2^(32−n)); the first address must be divisible by the block size; the first address is the network address and the last is the broadcast.
  • Hosts per block = 2^(32−n) − 2 (minus network & broadcast).
  • CIDR enables VLSM (different masks inside one network) and route aggregation / supernetting (many routes → one).
  • Today's Internet is classless; “class” knowledge is still tested because default masks are used in exams and legacy protocols (RIPv1).
Example: A company needs 500 hosts. Classful → Class B (65 534 hosts, waste = 65 034). CIDR → /23 (510 hosts, waste = 10).

What does /27 mean? How many hosts?
27 network bits, 5 host bits → 2⁵ − 2 = 30 usable hosts, mask 255.255.255.224.
Why was CIDR introduced?
To stop IPv4 depletion (wasted classful space) and shrink the global routing table through aggregation.

8. Class A – E Addressing Deep Dive

The class is identified from the leading bits of the first octet. This lets a router know the default mask without being told.

Key concepts

  • Class A: first bit 0 → 0–127. Network = 8 bits (7 usable → 2⁷ = 128 values, minus 0.x and 127.x ⇒ 126 networks), host = 24 bits → 2²⁴−2 = 16,777,214 hosts.
  • Class B: leading 10 → 128–191. Network = 16 bits (14 free → 16,384 networks), hosts 2¹⁶−2 = 65,534.
  • Class C: leading 110 → 192–223. Network = 24 bits (21 free → 2,097,152 networks), hosts 2⁸−2 = 254.
  • Class D: leading 1110 → 224–239, multicast (no netid/hostid concept). e.g. 224.0.0.5 = all OSPF routers.
  • Class E: leading 1111 → 240–255, reserved for research/future use.
  • Formulas: #networks = 2^(netbits − class prefix bits); #hosts/network = 2^(hostbits) − 2.
  • Private ranges (RFC 1918): 10.0.0.0/8 (A), 172.16.0.0 – 172.31.255.255 (/12, B), 192.168.0.0/16 (C). Not routable on the Internet.

Why subtract 2 from the host count?
All-0 host bits = network address; all-1 host bits = directed broadcast address.
Which class is 10.20.30.40 and is it private?
Class A and private (10/8).

9. Special Addresses, Loopback & Troubleshooting

Some IPv4 addresses are reserved for special jobs. Loopback 127.0.0.0/8 never leaves the machine — packets sent to it are returned by the local TCP/IP stack. It is how you test the software stack and how a client talks to a server on the same machine (“localhost”).

Key concepts

  • 0.0.0.0 — “this host / unknown” (source during DHCP discovery) and, in routing, the default route 0.0.0.0/0.
  • 127.0.0.0/8 — loopback (127.0.0.1 = localhost). 16 million addresses wasted by design.
  • 255.255.255.255 — limited broadcast: all hosts on the local network, routers do not forward it.
  • Host bits all 1 — directed broadcast to a specific network (e.g. 192.168.1.255). Host bits all 0 — network address (cannot be assigned).
  • 169.254.0.0/16 — APIPA / link-local; a host assigns itself this when DHCP fails — a clue in troubleshooting.
  • Troubleshooting ladder (bottom-up): ping 127.0.0.1 → ping own IP → ping default gateway → ping remote IP (8.8.8.8) → ping a domain name. The first failure tells you the layer: stack, NIC/config, LAN, routing/ISP, DNS.
  • Tools: ping (ICMP echo), traceroute / tracert (TTL trick), ipconfig / ifconfig / ip a, arp -a, nslookup / dig, netstat / ss.

Click a question to reveal the answer.

You can ping 127.0.0.1 but not 8.8.8.8. What next?
Stack is fine. Check own IP, default gateway, then routing/ISP. If 8.8.8.8 works but google.com does not → DNS.
Why does a host get 169.254.x.x?
DHCP server unreachable; OS self-assigned a link-local address (APIPA).
Is 127.0.0.1 sent on the wire?
No. The OS loops it back internally at the IP layer.

10. IP Conversion Practice: Netid, Hostid, Network & Broadcast Addresses

This long practice block drills one skill: from any IP (and mask) find class, netid, hostid, network address, broadcast address and host range. All answers come from one operation — the bitwise AND with the mask.

Key concepts

  • Network address = IP AND mask (host bits → 0).
  • Directed broadcast = network address OR (NOT mask) (host bits → 1).
  • Limited broadcast = 255.255.255.255 (never routed).
  • First host = network + 1, last host = broadcast − 1, hosts = 2^h − 2.
  • Two hosts are on the same network iff (IP₁ AND mask) = (IP₂ AND mask). If not, the sender must send via the default gateway.
  • Decimal shortcut for non-/8/16/24 masks: block size = 256 − mask octet; network = the multiple of block size ≤ IP octet; broadcast = network + block − 1.

• 10.5.6.7/8 → Net 10.0.0.0, Bcast 10.255.255.255
• 150.10.20.30 (Class B) → Net 150.10.0.0, Bcast 150.10.255.255
• Same network? 192.168.1.70 & 192.168.1.130 with /25 → .0 vs .128 → No.

11. Subnetting & Borrowing Bits

Subnetting divides one network into smaller sub-networks by borrowing bits from the host portion and treating them as extra network (subnet) bits. Benefits: smaller broadcast domains, better security, less waste, easier administration.

Key concepts

  • Borrow n bits → 2ⁿ subnets. Remaining host bits h → 2ʰ − 2 usable hosts per subnet.
  • New mask = old mask + n extra ones. Block size (magic number) = 256 − (interesting mask octet).
  • Steps: ① identify class / prefix ② decide borrowed bits n from required subnets ③ compute new mask ④ list subnet addresses by block-size jumps ⑤ for each: network, first, last, broadcast.
  • Classic rule: older exams discard the all-0 and all-1 subnets (usable subnets = 2ⁿ − 2). Modern devices (ip subnet-zero, CIDR) use all 2ⁿ. Always read the question — state your assumption in an interview.
  • Subnets are connected by routers; each subnet is its own broadcast domain.
  • Fixed-length subnetting (FLSM) gives all subnets the same size — simple but wasteful when needs differ → VLSM.
Worked: 192.168.1.0/24, need 6 subnets → n=3 (2³=8 ≥ 6) → /27, mask 255.255.255.224, block 32, hosts 30. Subnets: .0, .32, .64, .96, .128, .160, .192, .224.

12. Subnet Mask Design (from requirements to mask)

In design problems you are given requirements — number of subnets and/or hosts per subnet — and must choose the mask. Convert each requirement into a bit count, check it fits in the available bits, then write the mask.

Key concepts

  • Hosts requirement H → h = ⌈log₂(H + 2)⌉ host bits.
  • Subnet requirement S → n = ⌈log₂ S⌉ subnet bits (or ⌈log₂(S+2)⌉ for the old no-zero-subnet rule).
  • Feasibility: classPrefix + n + h ≤ 32. If h is fixed, prefix = 32 − h; extra bits go to subnets.
  • Mask from prefix: k = prefix mod 8 leading ones in the “interesting” octet. Octet value = 256 − 2^(8−k).
  • Wildcard mask = 255.255.255.255 − mask (used in ACLs and OSPF network statements): /26 → 0.0.0.63.
  • Find the subnet of any host: subnet number = host octet ÷ block size (integer division) × block size.
  • Maximise hosts or maximise subnets? The two trade off; the question wording (“at least”, “at most”, “maximum”) tells which.
Quick table: /25=128 (126 hosts) · /26=192 (62) · /27=224 (30) · /28=240 (14) · /29=248 (6) · /30=252 (2) · /31 point-to-point (RFC 3021).

13. VLSM — Variable Length Subnet Masking

VLSM lets you apply different masks to different subnets of the same network, so each subnet is sized for its actual need. It needs a classless routing protocol (RIPv2, OSPF, EIGRP, BGP) that carries the mask in updates.

Key concepts

  • Algorithm: (1) list requirements, (2) sort in descending order, (3) for each find the smallest block 2^h ≥ need + 2, (4) allocate from the lowest free address, aligned to the block size, (5) continue from the end of the previous block.
  • Sorting biggest-first avoids alignment fragmentation: a large block must start at a multiple of its size.
  • Point-to-point WAN links get /30 (or /31).
  • Address use efficiency = Σ needs / Σ allocated; VLSM typically reaches 90 %+.
  • Summarisation is easier when you allocate contiguous blocks by region.
  • Verification: no two ranges overlap; each network address is a multiple of its block size; everything fits inside the parent block.
Worked allocation (192.168.10.0/24): A=100→/25 .0–.127 · B=50→/26 .128–.191 · C=25→/27 .192–.223 · D=10→/28 .224–.239 · Link=2→/30 .240–.243. Remaining .244–.255 stays free.

14. Routing Tables, CIDR Blocks & Longest Prefix Match

A routing table maps destination prefixes to a next hop and outgoing interface. Under CIDR, entries are prefix/length blocks and the router chooses the most specific (longest prefix) match.

Key concepts

  • Columns: destination network, mask/prefix, next hop (gateway), interface, metric. Sources: connected (C), static (S), dynamic (RIP/OSPF/BGP).

  • Valid CIDR block: contiguous addresses, count is a power of 2, and first address divisible by the count.
  • Find block range from a.b.c.d/n: size = 2^(32−n); start = address rounded down to a multiple of size; end = start + size − 1.
  • Administrative distance breaks ties between sources: connected 0, static 1, EBGP 20, OSPF 110, RIP 120.
  • Forwarding is hop-by-hop: each router only knows the next hop, not the whole path.
Example: 200.1.2.130/26 → size 64, start 128 → block 200.1.2.128 – 200.1.2.191. First address divisible by 64? 128 = 2×64 ✔ valid.

15. Supernetting (Route Aggregation / Summarisation)

Supernetting is the reverse of subnetting: several contiguous networks are merged into one larger block by borrowing bits from the network part (shortening the prefix). It shrinks routing tables and is how ISPs advertise many customer routes as one.

Key concepts

  • Three conditions: (1) number of networks = power of 2, (2) addresses are contiguous, (3) the first network's address is divisible by the total block size.
  • New prefix = old prefix − log₂(number of networks). Four /24 → /22; eight /24 → /21.
  • Supernet mask: 4 × /24 → 255.255.252.0; 8 × /24 → 255.255.248.0; 2 × /24 → 255.255.254.0.
  • Quick check: find the first network's relevant octet and test divisibility by the count (e.g. 4).
  • Summary route = the first (lowest) network address with the new mask.
  • Compare: subnetting adds mask bits (splits), supernetting removes mask bits (merges), VLSM uses varied masks inside one network.
Worked: 192.16.8.0, 192.16.9.0, 192.16.10.0, 192.16.11.0 → 8 divisible by 4 ✔ → 192.16.8.0/22, 1022 hosts.

16. Error Detection Basics: Single-Bit vs Burst Errors

Real channels are noisy (thermal noise, crosstalk, impulse noise, attenuation, interference). Receivers must detect corrupted frames and either correct them (FEC) or request retransmission (ARQ).

Key concepts

  • Single-bit error: exactly one bit in the data unit flipped. Rare in serial links because noise lasts longer than a bit time (more common in parallel transfers).
  • Burst error: two or more bits corrupted. Length is measured from the first to the last corrupted bit — the bits between them may or may not be wrong.
  • Burst length ≈ data rate × noise duration. Higher data rate → the same noise burst damages more bits.
  • Redundancy is the core idea: send extra bits derived from the data. Methods in the video: parity (simple, 2-D), CRC, checksum, Hamming codes.
  • Detection vs correction: detection needs fewer redundant bits and is followed by retransmission (ARQ); correction (FEC) needs many more bits but avoids retransmission — useful for satellite, deep space, storage.
  • Where used: parity (memory / serial), CRC (Ethernet, Wi-Fi, PPP, storage), checksum (IP, TCP, UDP, ICMP), Hamming/ECC (RAM).

Burst, because noise events last longer than one bit duration, especially at high data rates.

Bits 3 to 6 differ (positions 3..7): from first to last differing position = 5.

Detection tells you something is wrong; correction also locates and fixes it, costing more redundancy.

17. Hamming Distance, Error Detection/Correction Capability & Hamming Code

Hamming distance between two equal-length words is the number of positions in which they differ. The minimum distance dmin of a code (smallest distance between any two valid codewords) determines how many errors it can detect and correct.

Key concepts

  • Detect s errors: dmin ≥ s + 1 (an s-bit error cannot turn one codeword into another).
  • Correct t errors: dmin ≥ 2t + 1 (spheres of radius t around codewords must not overlap).
  • Detect-and-correct combo: dmin ≥ s + t + 1 with s ≥ t.
  • Hamming (7,4) code: m = 4 data bits + r = 3 parity bits (placed at positions 1, 2, 4 — powers of 2). Condition 2^r ≥ m + r + 1. It corrects any single-bit error: the parity-check result (syndrome) is the binary position of the wrong bit.
  • Parity bit rules: p1 covers positions with bit 0 set (1,3,5,7), p2 covers (2,3,6,7), p4 covers (4,5,6,7).
  • Extended Hamming (SECDED) adds one overall parity bit: Single-Error-Correct, Double-Error-Detect — used in ECC RAM.
Hamming (7,4) example: data d3d5d6d7 = 1 0 1 1 → p1 = d3⊕d5⊕d7 = 1⊕0⊕1 = 0 · p2 = d3⊕d6⊕d7 = 1⊕1⊕1 = 1 · p4 = d5⊕d6⊕d7 = 0⊕1⊕1 = 0 → codeword (pos1..7) = 0 1 1 0 0 1 1. If position 5 flips, syndrome = 101₂ = 5 → fix bit 5.

18. Simple Parity & Two-Dimensional Parity

Parity checking is the simplest redundancy scheme. A single parity bit is appended so that the count of 1s is even (even parity) or odd (odd parity).

Key concepts

  • Simple parity: overhead 1 bit per unit; detects every odd number of flipped bits; fails if an even number of bits flip (the parity stays valid). Cannot correct or locate.
  • 2-D parity: arrange the data in a grid, compute a parity bit for every row and every column plus a corner bit. Overhead for r×c data = r + c + 1 bits.
  • Correction of a single-bit error: the failing row and failing column intersect at the damaged bit — flip it.
  • Detection power of 2-D parity: guarantees detection of any 1, 2 or 3 errors and most bursts; misses patterns where 4 errors sit at the corners of a rectangle (each row & column still even).
  • Burst performance: a burst shorter than the row length is caught because it flips parity in at least one column.
  • Trade-off: more redundancy → more capability. Parity is cheap hardware (XOR tree) but weak versus CRC.
Even parity of 1011001 (four 1s) → parity bit 0 → 10110010. Received 10100010 (three 1s, odd) → error detected. Received 10101010 vs 10110010 (two bits flipped, still even) → parity passes → error missed.

19. CRC — Cyclic Redundancy Check & Polynomial Notation

CRC treats the data as a big binary polynomial and divides it (using XOR / modulo-2 arithmetic, no carries) by an agreed generator polynomial. The remainder is the CRC appended to the frame; the receiver repeats the division and expects remainder 0.

Key concepts

  • Generator of degree r (r+1 bits) → CRC is r bits. Example: x³ + x² + 1 ↔ 1101 (degree 3, 4 bits).
  • Sender: append r zeros to data → divide by generator (mod-2) → remainder is the CRC → send data + CRC.
  • Receiver: divide received codeword by the same generator → remainder 0 ⇒ accept, otherwise error.
  • Polynomial notation: bit i ↔ coefficient of xⁱ. 1101 = 1·x³ + 1·x² + 0·x + 1.
  • Guarantees (when generator has x⁰ term and ≥ 2 terms): detects all single-bit errors; all double errors if g doesn't divide x^k+1 for small k; all odd-bit errors if (x+1) is a factor; all burst errors of length ≤ r; most longer bursts (miss probability 2^−r).
  • Standards: CRC-8, CRC-16 (x¹⁶+x¹⁵+x²+1), CRC-32 (Ethernet, Wi-Fi, PNG, ZIP): x³² + x²⁶ + x²³ + … + 1.
  • Hardware: implemented with a shift-register and XOR gates — fast and cheap, which is why every link layer uses it.
Result: data 100100, generator 1101 → CRC = 001; frame = 100100001.

20. Checksum Method

The checksum divides the data into k-bit words, adds them using one's-complement arithmetic (a carry out of the MSB is wrapped around and added back) and sends the complement of the sum. It is implemented in software in IP, ICMP, UDP and TCP (16-bit).

Key concepts

  • Sender: split into words (pad if needed) → add all words with end-around carry → complement → put in the checksum field (initially zero while computing).
  • Receiver: add all words including checksum, wrap carries, complement → result 0 (sum = all 1s) ⇒ accept.
  • Where: IPv4 checksum covers only the header (recomputed at every router because TTL changes); TCP/UDP cover pseudo-header + header + data.
  • Pros: trivial to compute in software, small overhead (16 bits). Cons: weaker than CRC — misses compensating errors, word swaps, adding zero words. That is acceptable because link-layer CRC catches most noise and checksum catches router/software bugs end-to-end.
  • UDP over IPv4: checksum optional (0 = unused); over IPv6: mandatory.
Example (4-bit words): 7, 11, 12, 6 → 7+11=18 (10010) → wrap → 3 ; 3+12=15 ; 15+6=21 (10101) → wrap → 6 ; complement of 0110 = 1001 = 9. Receiver: 7+11+12+6+9 → …→ 1111 ⇒ OK.

21. Transmission Delay vs Propagation Delay

End-to-end latency has four components. Flow-control analysis (stop-and-wait, sliding window) uses just two: transmission delay (time to push all bits of a packet onto the wire) and propagation delay (time for one bit to travel the medium).

Key concepts

  • Transmission delay Tt = L / B. L = packet size (bits), B = bandwidth (bps). Depends on packet size and link rate — not distance.
  • Propagation delay Tp = d / v. d = link length, v = propagation speed (≈ 2×10⁸ m/s). Depends on distance and medium — not packet size.
  • Queuing delay: waiting in router buffers — varies with traffic; processing delay: header inspection, checksum, route lookup (µs).
  • Ratio a = Tp / Tt is the key number: a ≪ 1 (LAN) wire is “short”, a ≫ 1 (satellite) wire is “long” and stop-and-wait wastes the link.
  • RTT = time for a small packet to go and return ≈ 2·Tp (+ Tt of data and ack). Bandwidth–delay product (BDP) = B × RTT = bits “in flight” needed to keep the pipe full.
  • Unit traps: bytes vs bits (×8), K/M/G = 10³/10⁶/10⁹ for rates but 2¹⁰ etc. for sizes in some exams, ms vs µs.
Worked: 1 000-byte packet = 8 000 bits, B = 1 Mbps → Tt = 8 ms. Link 2 000 km → Tp = 2×10⁶ / 2×10⁸ = 10 ms. a = 1.25. One-way = 18 ms; RTT (ack negligible) = 20 ms + 8 ms.

22. Stop-and-Wait ARQ

Stop-and-Wait is the simplest flow-control + error-control protocol: send one frame, stop, and wait for its acknowledgement before sending the next. ARQ = Automatic Repeat reQuest.

Key concepts

  • Sender window = 1, receiver window = 1. Sequence numbers need only 1 bit (0,1) — to tell a new frame from a duplicate caused by a lost ACK.
  • Timer: started on every send; on timeout retransmit. Timeout ≥ RTT (≈ Tt + 2Tp + Tack).
  • Lost frame → no ACK → timeout → resend. Lost ACK → timeout → resend → receiver detects duplicate by seq number, discards and re-ACKs. Delayed ACK → premature timeout, duplicates handled again by seq numbers. Corrupt frame → discarded (acts as lost) or NAK.
  • Cycle time: Tt (send) + 2·Tp (go & return) + Tt(ack, usually ignored).
  • Efficiency η = useful time / total = Tt / (Tt + 2Tp) = 1 / (1 + 2a). Throughput = η × B.
  • Pros: trivial, minimal buffer. Cons: awful utilisation on long/fat pipes; hence sliding window.
Worked: L = 1 000 bits, B = 1 Mbps (Tt = 1 ms), Tp = 20 ms → η = 1/(1+40) = 2.4 %. Throughput = 24 kbps on a 1 Mbps link!

23. Efficiency, RTT & Throughput (Formulas Toolkit)

Every flow-control problem in interviews and GATE reduces to three numbers: Tt, Tp and the window size N. This section consolidates the formulas.

Key concepts

  • Utilisation / efficiency: η = (time spent sending useful data) / (total cycle) = N·Tt / (Tt + 2Tp), capped at 1.
  • Stop-and-wait: η = 1/(1+2a). Sliding window with window N: η = N/(1+2a), cap 1.
  • Throughput = η × B (bits delivered per second) = N·L / (Tt + 2Tp) when η < 1.
  • Minimum window to saturate the link: N = 1 + 2a = ⌈(Tt + 2Tp)/Tt⌉.

  • Effective bandwidth with errors: if a fraction p of frames is lost, SW efficiency ≈ (1−p)/(1+2a); GBN ≈ (1−p)/(1+2a p) for large windows (each loss costs N retransmissions).

24. Sliding Window Protocols — Concepts

In sliding window protocols the sender may transmit up to N frames without waiting for an ACK (pipelining). The window is a range of sequence numbers that “slides” forward as acknowledgements arrive. This fills the pipe and raises efficiency to N/(1+2a).

Key concepts

  • Sender window = sequence numbers of frames sent but unacknowledged + those allowed to send. Receiver window = range of frames it will accept.
  • Sequence number field of k bits → numbers 0 … 2ᵏ−1 reused cyclically (modular arithmetic). The space must be large enough to prevent old/new frame ambiguity.
  • Cumulative ACK (“received everything up to n−1; send n next”) vs individual ACK.
  • Piggybacking: ACK is carried inside an outgoing data frame to save bandwidth.
  • Flow control ↔ window: TCP's receiver advertises a window (rwnd) so the sender never overruns the receiver's buffer.
  • Comparison: window sizes — Stop-and-wait 1/1, GBN N/1, SR N/N; buffer needs increase in the same order.

25. Go-Back-N (GBN) Protocol

Go-Back-N pipelines up to N frames, but the receiver accepts only in-order frames (receiver window = 1). When a frame is lost or damaged, the sender goes back and retransmits that frame and all following frames.

Key concepts

  • Window sizes: Ws = N ≤ 2ᵏ − 1, Wr = 1. Minimum sequence bits = ⌈log₂(N + 1)⌉.
  • Receiver: accepts frame with expected number, delivers it, sends cumulative ACK for next expected; discards out-of-order frames (no buffering) and re-ACKs the last good one.
  • Sender: one timer for the oldest unacked frame; on timeout resend the whole outstanding window.
  • Efficiency (no loss) η = N/(1+2a); with loss probability p each lost frame costs ≈ N retransmissions → avg transmissions per frame ≈ 1 + p·N … (approx. 1/(1−p) for SR vs (1−p+Np)/(1−p) for GBN).
  • Pros: simple receiver, little buffer, cumulative ACKs reduce traffic. Cons: wasteful on lossy / high BDP links because correct frames are re-sent.
  • Real-world: classic TCP behaves like GBN with cumulative ACKs (plus SACK extension to avoid wasteful resends).
Example: sent 0,1,2,3,4,5,6, frame 3 lost → receiver ACKs 0,1,2 then keeps asking for 3; sender times out and re-sends 3,4,5,6 (4 frames) although 4,5,6 had arrived safely.

26. Selective Repeat (SR) Protocol

Selective Repeat retransmits only the lost/damaged frames. The receiver has a window too (Wr = N), buffers out-of-order frames, sends individual ACKs, and re-orders before delivering to the upper layer.

Key concepts

  • Sender: a timer per frame (or a single timer with bookkeeping); only the timed-out frame is resent.
  • Receiver: accepts any frame in its window, buffers, ACKs it; delivers in-order data and slides when the leftmost gap is filled. Frames below the window are re-ACKed (duplicates).
  • NAK (negative ACK) can speed recovery without waiting for timeout.
  • Pros: best bandwidth efficiency on lossy links. Cons: complex, more buffer & sorting logic at receiver.
  • Real-world: TCP + SACK option behaves like selective repeat; used in satellite and wireless links.

27. IPv4 Header & TOS Bits

The IPv4 header is 20 bytes minimum (5 words) and up to 60 bytes (with 40 bytes of options). Every router reads it to forward the packet.

Key concepts

  • Version (4 b) = 4. IHL (4 b) = header length in 32-bit words; min 5 (20 B), max 15 (60 B). Byte length = IHL × 4.
  • TOS / DSCP (8 b): originally 3-bit precedence + D (delay), T (throughput), R (reliability), C (cost) flags; now 6-bit DSCP (DiffServ) + 2-bit ECN (congestion notification).

28. TTL & IP Fragmentation

TTL prevents packets from looping forever. Fragmentation lets a datagram cross links whose MTU (Maximum Transmission Unit) is smaller than the packet — Ethernet MTU is 1 500 B.

Key concepts

  • TTL: set by sender (64/128/255); every router decrements; when it reaches 0 the router discards the packet and sends ICMP type 11. traceroute sends probes with TTL 1, 2, 3… to discover each hop.
  • Fragmenting: each fragment gets a copy of the header (same Identification), its own Total length, MF=1 for all but the last, and Fragment offset = start-byte / 8.
  • Rule: data per fragment ≤ MTU − header and (except last) a multiple of 8. With MTU 1 500 and 20-byte header → 1 480.
  • DF=1 (Don't Fragment): router must drop and reply ICMP “Fragmentation needed” — the basis of Path MTU Discovery.
  • Reassembly only at the destination (routers may re-fragment further). If one fragment is lost the whole datagram is lost → retransmission of everything, a reason to avoid fragmentation (TCP uses MSS = MTU − 40).
  • Cost: extra header overhead (20 B per fragment), CPU load, and security issues (fragment attacks, teardrop, tiny fragment).
Number of fragments = ⌈ data / (floor((MTU − hdr)/8)×8) ⌉ = ⌈3980 / 1480⌉ = 3. Last fragment: offset 370, data 1 020, total length 1 040, MF = 0.

29. IP Options & Source Routing

30. TCP Header: Sequence & Acknowledgement Numbers

TCP is the Transport-layer protocol offering a reliable, ordered, connection-oriented byte stream. Its header is 20–60 bytes; the sequence/ack numbers give ordering, reliability and flow control.

Key concepts

  • Ports (16 b) identify processes: well-known 0–1023 (80 HTTP, 443 HTTPS, 22 SSH, 25 SMTP, 53 DNS), registered 1024–49151, dynamic 49152–65535. A connection (socket pair) = (src IP, src port, dst IP, dst port).
  • Sequence number = number of the first byte in the segment (TCP numbers bytes, not segments). Initial value (ISN) is random for security.
  • Acknowledgement number = number of the next byte expected (cumulative); valid only when ACK flag = 1.
  • HLEN (4 b) in words (min 5 → 20 B, max 15 → 60 B). Window (16 b) receiver's advertised buffer (flow control); with Window Scale option up to 1 GB.
  • Checksum covers a pseudo-header (src/dst IP, protocol, length) + TCP header + data — mandatory. Urgent pointer valid with URG.
  • Options: MSS (typically 1 460), window scaling, SACK permitted, timestamps.
  • Segment sent with seq = 1000, 500 bytes of data → receiver ACKs 1500.
Worked: Host A sends segments seq=1000 (500 B), seq=1500 (500 B), seq=2000 (500 B). If the 2nd is lost the receiver keeps ACKing 1500 (duplicate ACKs). Three duplicate ACKs trigger fast retransmit of 1500.

31. TCP Flags, 3-Way Handshake & Connection Termination

TCP must establish shared state (sequence numbers, window, options) before data flows. This is done with the three-way handshake; closing uses a four-way handshake because each direction is closed independently (half-close).

Key concepts

  • Flags: SYN synchronise seq numbers (open) · ACK ack field valid · FIN sender done · RST abort/refuse · PSH deliver now · URG urgent data.
  • Handshake: ① Client → SYN(seq=x) ② Server → SYN+ACK(seq=y, ack=x+1) ③ Client → ACK(ack=y+1). SYN and FIN each consume one sequence number even without data; a pure ACK consumes none.
  • Why three, not two? To avoid old duplicate SYNs opening half-connections and to let both sides confirm each other's ISN.
  • Termination: FIN → ACK → FIN → ACK. The side that closes first enters TIME_WAIT (2×MSL, ~60-120 s) so that the last ACK can be retransmitted and stray packets expire.
  • RST is sent to a closed port (“connection refused”) or to abort abruptly. Port scanners (nmap) use SYN/FIN/RST responses to map open ports.
  • Half-open vs half-close: half-open = server waiting after SYN+ACK (SYN flood target); half-close = one direction FIN-ed, the other still sending.
  • States to know: CLOSED, LISTEN, SYN_SENT, SYN_RCVD, ESTABLISHED, FIN_WAIT_1/2, CLOSE_WAIT, LAST_ACK, TIME_WAIT.

Why does TCP need TIME_WAIT?
To ensure the final ACK reaches the peer (it may need to resend its FIN) and to let delayed segments from the old connection die before the same 4-tuple is reused.
How many sequence numbers does a SYN consume?
One.
Can data be sent in the third handshake ACK?
Yes; the third segment may already carry data (and TCP Fast Open allows data in SYN).

32. SYN Flooding Attack (DoS)

A SYN flood abuses the three-way handshake. The attacker sends a stream of SYN segments (usually with spoofed source IPs) and never completes the handshake. The server allocates a Transmission Control Block for each half-open connection and keeps retrying SYN+ACK until its backlog queue is full, so legitimate clients are refused: a Denial of Service.

Key concepts

  • Attack cost is low (one small packet per connection) while server cost is memory + timers.
  • Spoofed IPs mean replies never return and attackers are hard to trace.
  • SYN cookies: server encodes connection info in the ISN of its SYN+ACK and stores nothing; state is rebuilt only if a valid ACK returns.
  • Other mitigations: reduce SYN-RECEIVED timeout, increase backlog, recycle oldest half-open entries, rate-limit SYN per source, firewall / SYN proxy / CDN scrubbing, ingress filtering to drop spoofed sources.
  • Related: UDP flood, ICMP (ping) flood, Smurf, Slowloris (HTTP), DDoS amplification (DNS/NTP).
  • Detect: huge count of connections in SYN_RECV in netstat -an.

How do SYN cookies work?
The server sets its ISN = hash(secret, src/dst IP+port, time) and keeps no state; a genuine client's ACK (ack = ISN+1) lets the server validate and reconstruct the connection.
Why is the attack effective with spoofed IPs?
Replies go to nonexistent hosts, so the half-open entry lingers until timeout and no RST ever clears it.

33. Congestion Control: Policies, TCP Slow Start, AIMD, Leaky & Token Bucket

Congestion = too much traffic for the network to carry; queues overflow and packets are dropped, causing retransmissions and even more load. Flow control protects the receiver; congestion control protects the network.

Key concepts

  • Open-loop (prevention) policies: retransmission policy (timers tuned), window policy (SR better than GBN), acknowledgement policy, discard policy, admission policy (virtual circuits). Closed-loop (reaction): backpressure, choke packets, implicit signalling (loss/delay), explicit signalling (ECN).
  • TCP effective window = min(rwnd, cwnd).
  • Slow start: cwnd starts at 1 MSS (IW10 today) and doubles every RTT (+1 per ACK) until it reaches ssthresh.
  • Congestion avoidance (AIMD): beyond ssthresh increase additively (+1 MSS per RTT); on loss decrease multiplicatively.
  • Reaction: Timeout (severe) → ssthresh = cwnd/2, cwnd = 1 (Tahoe and Reno). 3 duplicate ACKs (mild) → Tahoe: same as timeout; Reno fast retransmit + fast recovery: ssthresh = cwnd/2, cwnd = ssthresh (+3), then linear growth.
  • Leaky bucket: shapes bursty input into a constant output rate (buffer drains at fixed rate; overflow dropped). Token bucket: tokens accumulate at rate r up to capacity b; a packet needs a token; allows bursts up to b then rate r. Max burst time S = b/(M − r) for peak rate M.
  • Modern variants: CUBIC (Linux default), BBR (model-based), Vegas (delay-based).
Worked: cwnd = 1,2,4,8 (slow start, ssthresh = 16) → 16 → 17, 18 … loss by timeout at 20 → ssthresh = 10, cwnd = 1 → 2,4,8,10 → 11 …

Flow control vs congestion control?
Flow: sender ↔ receiver buffer (rwnd). Congestion: sender ↔ network capacity (cwnd).

It starts from a small window — but grows exponentially; it is "slow" relative to sending the full window immediately.

34. TCP/UDP Timers & TCP vs UDP Comparison

TCP uses four timers; UDP, being connectionless and unreliable, uses none. Choosing between them is a standard interview question.

Key concepts

  • Retransmission timer: if ACK doesn’t arrive within RTO, resend. RTO adapts: SRTT (smoothed RTT) and RTTVAR (variance); RTO = SRTT + 4·RTTVAR; exponential back-off on repeated loss; Karn's algorithm ignores ambiguous samples.
  • Persistence timer: when the receiver advertises window 0 the sender periodically sends 1-byte probes — prevents deadlock if the window-update ACK is lost.
  • Keepalive timer: detects dead peers on idle connections (default 2 hours, optional).
  • TIME-WAIT timer: 2×MSL after active close.
  • TCP vs UDP: pick TCP when you need reliability and ordering; UDP when latency matters and the app can tolerate/handle loss. QUIC (HTTP/3) rebuilds reliability on top of UDP to avoid head-of-line blocking and to ship quickly in user space.
  • Segment vs datagram: TCP is a stream (no message boundaries); UDP preserves message boundaries.

35. Random Access MAC: Pure/Slotted Aloha & CSMA

On a shared medium, a Medium Access Control (MAC) protocol decides who may transmit. Random access protocols have no central control — stations transmit when they have data and handle collisions.

Key concepts

  • Pure Aloha (1970, Hawaii): transmit any time; if no ACK → wait random time, retry. Vulnerable time = 2·Tfr. Throughput S = G·e−2G, max 18.4 % at G = ½.
  • Slotted Aloha: time divided into slots of Tfr; stations transmit only at slot start. Vulnerable time = Tfr. S = G·e−G, max 36.8 % at G = 1.
  • CSMA (Carrier Sense Multiple Access): “listen before talk” reduces collisions but cannot eliminate them because of propagation delay (two stations may both sense idle).
  • Persistence methods: 1-persistent — transmit immediately when idle (collisions likely if ≥ 2 waiting; used in Ethernet). Non-persistent — if busy wait random time then sense again (less collisions, more delay). p-persistent — when idle, transmit with prob p, else wait a slot (slotted channels).
  • CSMA/CD adds collision detection (wired); CSMA/CA adds collision avoidance (wireless) — next topic.
  • Performance ranking (high load): CSMA family ≫ Slotted Aloha > Pure Aloha.
Worked: Frame 200 bits at 200 kbps → Tfr = 1 ms. Pure Aloha G=1 frame/ms → S = e⁻² ≈ 13.5 % → ≈ 135 frames/s successful. Slotted at G=1 → 36.8 % → 368 frames/s.

36. CSMA/CD — Collision Detection (Ethernet)

CSMA/CD is the MAC of classic half-duplex Ethernet: sense the carrier, transmit, keep listening while sending; if a collision is detected, stop at once, send a jam signal and back off.

Key concepts

  • Algorithm: ① sense channel; if idle send ② while sending monitor; if collision → send jam ③ increment attempt counter n ④ wait random backoff K×slot where K ∈ [0, 2ⁿ−1] ⑤ retry; abort after 16 attempts.
  • Condition for detection: transmission time ≥ round trip propagation, i.e. Tt ≥ 2·Tp ⇒ L ≥ 2·Tp·B. This is why Ethernet has a 64-byte minimum frame and why the maximum cable length is bounded.
  • Slot time = 2·Tp (+ jam) = 51.2 µs for 10 Mbps Ethernet = 512 bit times.
  • Efficiency ≈ 1 / (1 + 6.44·a) where a = Tp/Tt (large frames and short cables are better).
  • Wired only: a wireless station cannot listen while sending (its own signal overwhelms), and hidden terminals exist → CSMA/CA with ACK, random backoff and optional RTS/CTS (Wi-Fi 802.11 DCF).
  • Obsolete on switched full-duplex Ethernet, but the minimum-frame-size derivation remains a favourite exam question.
Worked: 10 Mbps, cable 2.5 km each way, v = 2×10⁸ → Tp = 12.5 µs → 2Tp = 25 µs → L_min = 25 µs × 10⁷ = 250 bits (Ethernet chose 512 for margin and repeaters).

37. Controlled Access: Reservation, Polling & Token Passing

Controlled-access protocols avoid collisions entirely: stations take turns, so performance stays predictable (deterministic) even under heavy load.

Key concepts

  • Reservation: time divided into intervals; a reservation frame precedes data; only stations that reserved may send.
  • Polling: a primary station asks each secondary in turn (Poll); with Select it announces data for a secondary. Pros: no collisions, priorities. Cons: polling overhead, single point of failure (primary), latency. Efficiency η = Tt / (Tt + Tpoll).
  • Token passing: a special frame (token) circulates; only the holder transmits (for a bounded token-holding time), then passes the token. Standards: IEEE 802.5 Token Ring, FDDI, Token Bus.
  • Ring latency = Tp (ring propagation) + N × station delay. Efficiency for early token release: η = 1/(1 + a/N); for delayed release: η = 1/(1 + (N+1)a/N), where a = Tp/Tt, N stations.
  • Failure handling: lost token → monitor station regenerates; duplicate token → removed; station failure → bypass relay / dual ring.
  • Contrast: random access wins at low load (no wait), controlled access wins at high load (no collisions).

38. Routing Algorithms: Distance Vector vs Link State

Routing algorithms fill the routing tables automatically. They are classified as distance vector and link state; between autonomous systems the Internet uses path vector (BGP).

Key concepts

  • Distance vector (DV): each router knows only its neighbours and the distance vector to all destinations. Update rule (Bellman-Ford): Dx(y) = min over neighbours v of { c(x,v) + Dv(y) }. Information travels “by rumour”.
  • Count-to-infinity: when a link fails, routers keep increasing each other's distances (bad news travels slowly). Mitigation: split horizon (don't advertise a route back to where it came from), poison reverse (advertise it with infinite cost), hold-down, max metric (RIP ∞ = 16).
  • Link state (LS): each router floods a Link State Packet (neighbours + costs) to everyone, builds the same topology database, runs Dijkstra locally. Converges fast, loop-free, supports metrics and areas; costs more memory/CPU and flooding bandwidth.
  • Protocols: RIP (DV, UDP 520, hop count, 30 s updates), OSPF (LS, IP proto 89, cost by bandwidth, areas), IS-IS, EIGRP (advanced DV), BGP (path vector, TCP 179).
  • Static vs dynamic; intra-AS (IGP) vs inter-AS (EGP).
  • Complexity: DV message exchange O(neighbours) per round; LS O(N·E) flooding, Dijkstra O(N²) or O(E log N).

39. Circuit Switching vs Packet Switching (and Message Switching)

A switched network must decide how a message crosses intermediate nodes. Circuit switching reserves resources end-to-end; packet switching chops data into packets that share links on demand.

Key concepts

  • Circuit switching (telephone): 3 phases — setup, data transfer, teardown. Resources (bandwidth/time-slots) are reserved, so there is no congestion once connected, no per-packet header and delay is constant; but the setup delay is large and idle capacity is wasted. Multiplexing: FDM/TDM.
  • Packet switching (Internet): data split into packets with headers; routers store-and-forward. Efficient (statistical multiplexing), robust (re-route), cheap; but variable delay, jitter, congestion, packet loss, header overhead.
  • Datagram approach: each packet routed independently using the destination address (IP) — no setup, possible reordering. Virtual circuit: setup establishes a path & VC number; packets follow in order (ATM, MPLS).
  • Message switching: entire message stored and forwarded (telegram, email relays) — long delays, big buffers.
  • Pipelining benefit: splitting a message into packets lets different hops work in parallel — total time (M/P + h − 1)·P/B instead of h·M/B.
  • Rule of thumb: constant-rate long flows (voice) favour circuits; bursty data favours packets.
Worked: M = 1 Mb, B = 1 Mbps, h = 3 links. Message switching: 3 × 1 s = 3 s. Packet switching with 10 packets (0.1 Mb): (10 + 3 − 1) × 0.1 = 1.2 s.

  • Webmail (Gmail) uses HTTP between browser and server, but SMTP between servers.
  • Security: SPF, DKIM, DMARC fight spoofing; TLS protects in transit.

41. DNS — Hierarchy, Records & Queries

The Domain Name System is the Internet's distributed, hierarchical database that maps names → IP addresses (and more). It lets humans use www.example.com instead of numbers.

Key concepts

  • Hierarchy: Root (.) → Top-Level Domain (.com, .org, .in, .uk) → Second-level (example.com) → hosts (www). 13 logical root server identities (a–m) with hundreds of anycast instances.
  • Zones & name servers: a zone is delegated and served by authoritative servers (primary + secondary). Local recursive resolver (ISP/8.8.8.8) does the work for clients.
  • Recursive query: “give me the final answer” (client → resolver). Iterative query: server replies with the best referral and the asker continues (resolver → root/TLD/auth).
  • Caching everywhere (respecting record TTL) is why DNS scales. Negative caching for NXDOMAIN.
  • Records: A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), NS (name server), PTR (reverse lookup), TXT (SPF/verification), SOA (zone authority), SRV.
  • Transport: UDP/53 for queries (<512 B or EDNS 4096), TCP/53 for large replies and zone transfers (AXFR); DoH/DoT encrypt queries. DNSSEC signs records to stop spoofing.
  • Attacks: cache poisoning, DNS amplification DDoS, hijacking.

42. FTP, HTTP, ARP & ICMP

Four protocols that appear in every networking interview: two application-layer protocols (FTP, HTTP) and two helper protocols that glue layers 2 and 3 (ARP, ICMP).

Key concepts

  • FTP: file transfer with separate control (21) and data (20 / ephemeral) connections — “out-of-band” control. Active mode: server connects back to client (blocked by NAT/firewall); passive: client opens both. Needs authentication; unencrypted → use SFTP (SSH) or FTPS.
  • HTTP: text-based request/response, stateless (cookies/sessions add state). Methods: GET (read, idempotent), POST (create), PUT (replace), PATCH, DELETE, HEAD, OPTIONS. Status classes: 1xx info, 2xx success, 3xx redirect, 4xx client error, 5xx server error. HTTPS = HTTP over TLS (443).
  • HTTP versions: 1.0 (non-persistent), 1.1 (persistent, pipelining, Host header), 2 (binary, multiplexed streams, HPACK header compression), 3 (QUIC over UDP).
  • ARP: maps IP → MAC on the local network. Host broadcasts an ARP request, the owner unicasts the reply, the sender caches it (timeout ~minutes). To reach a remote host it ARPs for the default gateway, not the destination. Proxy ARP, Gratuitous ARP (duplicate-IP detection), RARP (MAC → IP, obsolete → BOOTP/DHCP).
  • ICMP: carried inside IP (protocol 1), reports errors and answers diagnostics; never sent about ICMP errors to avoid storms. Used by ping, traceroute, Path MTU discovery.
  • DHCP bonus (DORA): Discover, Offer, Request, Acknowledge — gets IP, mask, gateway, DNS (UDP 67/68).

Why does FTP use two connections?
Control channel stays open for commands while a fresh data connection is opened per transfer (so commands can be sent during transfer, e.g. abort).
Is HTTP stateless? How do websites remember you?
Yes; state is added through cookies, tokens or server-side sessions.
How does a host reach a destination outside its subnet via ARP?
It ARPs for its default gateway's MAC; the IP destination stays the remote host, the destination MAC is the gateway's.
Which ICMP types does ping and traceroute use?
Echo request (8) / echo reply (0); traceroute collects Time Exceeded (11) and final Echo Reply or Port Unreachable.

43. OSI Summary, Journey of a Packet & Final Interview Checklist

The course closes by tying everything back to the stack. Use this page as the master map when you revise.

Key concepts

  • Packet journey (A → web server across a router): App creates HTTP request → DNS resolves IP (UDP 53) → TCP handshake on port 443/80 → segments → IP packets (src/dst IP) → ARP resolves gateway MAC → Ethernet frame → switch forwards by MAC → router strips frame, decrements TTL, lookup (longest prefix), new frame to next hop → … → server decapsulates up the stack.

What happens when you type www.google.com and press Enter?

What stays the same and what changes across a router?
Same: src/dst IP, ports, payload. Changes: src/dst MAC, TTL, header checksum (and NAT rewrites IP/port).

Hub: L1 broadcast, one collision domain. Switch: L2, MAC table, collision domain per port. Router: L3, separates broadcast domains, routes by IP.
